The problem

The CI/CD pipeline from Example 5 deploys new images to EKS. Post-deployment, a smoke test script must call the payment-api's /health and /ready endpoints to confirm the service is accepting traffic before the pipeline marks the deployment as successful. The service may take 30–60 seconds to become ready after a rolling update, so the script must retry rather than fail immediately on the first unsuccessful response.

This is the last Tier 2 example. It introduces the test-alongside-implementation pattern — the script and its tests are built in the same session, not as separate afterthoughts. An automation script without tests is a script that will break silently; a script with tests is a script that can be safely changed.

Requirements
— Health checks: call /health and /ready on the deployed service URL
— Retry logic: exponential backoff with jitter, configurable max attempts and base delay
— Non-retryable errors: 4xx responses are not retried — only network errors and 5xx
— Structured logging: JSON log output with timestamp, level, attempt number, status code, and elapsed time
— Exit codes: 0 on success, 1 on exhausted retries, 2 on configuration error
— Tests: unit tests for the retry logic and backoff calculation, integration test with a mock HTTP server
— Type hints: full type annotations on all public functions
— CLI interface: --url, --max-attempts, --base-delay, --timeout arguments

Step 2 of 5
The naive approach

The naive smoke test is written in five minutes, works on the first deployment, and fails silently on the third. It has no retry logic, no structured output, no tests, and a retry loop that is actually just a fixed sleep.

scripts/smoke_test.py (naive)
import requests
import time
import sys

url = sys.argv[1]

# Fixed sleep — not a retry loop
time.sleep(30)

try:
    r = requests.get(f"{url}/health")
    if r.status_code == 200:
        print("Health check passed")
    else:
        print("Health check failed")
        sys.exit(1)
except Exception as e:
    print(f"Error: {e}")
    sys.exit(1)

# No /ready check
# No retry — one attempt only
# No structured output
# No tests
print("Smoke test passed")

Five failure modes, each common in automation scripts written under time pressure:

  • Reliability
    Fixed sleep instead of retry logic. time.sleep(30) always waits 30 seconds regardless of whether the service is ready after 5 seconds or not ready after 60. If the service takes 35 seconds to become ready, the script fails. If it takes 5 seconds, the script wastes 25 seconds on every deployment. A retry loop with backoff adapts to actual service readiness.
  • Reliability
    All exceptions treated identically. A connection timeout (transient, retryable) and a 404 Not Found (permanent, not retryable) both produce the same behaviour: print "Error" and exit 1. A proper retry implementation distinguishes between errors that are worth retrying and errors that indicate a configuration problem that retrying will not fix.
  • Observability
    No structured output. "Health check passed" and "Health check failed" are human-readable strings with no timestamp, no attempt number, no status code, and no elapsed time. A CI system parsing this output has no signal beyond pass/fail. Structured JSON logging lets downstream tools extract metrics, correlate with deployment events, and surface the attempt number at which a service became healthy.
  • Correctness
    Only /health checked, not /ready. Many services implement separate liveness and readiness probes. /health confirms the process is alive; /ready confirms it is ready to serve traffic. A service can be healthy but not ready during startup or when a dependency (like the RDS instance from Example 6) is unavailable. Checking only /health can produce a false positive smoke test result.
  • Maintainability
    No tests. The script has no unit tests for the retry logic, no mock for the HTTP calls, and no way to verify that changes to the script do not break its behaviour. Every change is a manual test. Over time, as the script is modified to accommodate new deployment patterns, bugs accumulate invisibly.
The core problem
The naive script is not a smoke test — it is a one-shot HTTP request with a fixed sleep preamble. A smoke test verifies that a deployment is healthy. This script verifies that the service was reachable 30 seconds after deployment started, once, with no retry, no readiness check, and no structured evidence of what it found. It produces false confidence in the same way as the naive shell script from Example 4.

scripts/retry.py (turn 1)
"""Reusable retry module for HTTP automation scripts."""
from __future__ import annotations

import logging
import random
import time
from dataclasses import dataclass, field
from typing import Callable, Optional, TypeVar, Union

import requests

T = TypeVar("T")


@dataclass
class RetryConfig:
    """Configuration for retry behaviour."""
    max_attempts: int = 5
    base_delay: float = 2.0      # seconds
    max_delay: float = 60.0     # seconds — cap on exponential growth
    backoff_factor: float = 2.0  # multiplier per attempt
    jitter: bool = True           # add randomness to avoid thundering herd


def is_retryable(
    error: Union[requests.Response, Exception]
) -> bool:
    """
    Determine whether an error warrants a retry attempt.

    Retryable: network errors, connection timeouts, 429, 5xx responses.
    Not retryable: 4xx client errors (except 429), programming errors.
    """
    if isinstance(error, requests.Response):
        if error.status_code == 429:
            return True   # Rate limited — retry after backoff
        if 500 <= error.status_code < 600:
            return True   # Server error — transient
        return False       # 4xx (except 429) — client error, retrying won't help

    # Network-level errors — always retryable
    retryable_exceptions = (
        requests.exceptions.ConnectionError,
        requests.exceptions.Timeout,
        requests.exceptions.ChunkedEncodingError,
    )
    return isinstance(error, retryable_exceptions)


def calculate_delay(attempt: int, config: RetryConfig) -> float:
    """
    Calculate the delay before the next retry attempt.

    Uses exponential backoff: base_delay * (backoff_factor ** attempt).
    Optionally adds uniform random jitter in [0, delay] to spread retries.
    Result is capped at max_delay.

    Args:
        attempt: Zero-indexed attempt number (0 = first retry).
        config: Retry configuration.

    Returns:
        Delay in seconds.
    """
    delay = min(
        config.base_delay * (config.backoff_factor ** attempt),
        config.max_delay,
    )
    if config.jitter:
        delay = random.uniform(0, delay)
    return delay


def retry_request(
    func: Callable[[], requests.Response],
    config: RetryConfig,
    logger: logging.Logger,
) -> requests.Response:
    """
    Execute func with retry logic according to config.

    Args:
        func: Callable that performs the HTTP request and returns a Response.
        config: Retry configuration.
        logger: Logger for attempt and backoff messages.

    Returns:
        The first successful Response.

    Raises:
        requests.HTTPError: If all attempts are exhausted.
        Exception: If a non-retryable exception is raised.
    """
    last_error: Optional[Union[requests.Response, Exception]] = None

    for attempt in range(config.max_attempts):
        try:
            response = func()
            if response.status_code < 400:
                return response

            if not is_retryable(response):
                logger.error(
                    "Non-retryable HTTP error",
                    extra={"status_code": response.status_code, "attempt": attempt + 1},
                )
                response.raise_for_status()

            last_error = response

        except requests.exceptions.RequestException as e:
            if not is_retryable(e):
                raise
            last_error = e

        if attempt < config.max_attempts - 1:
            delay = calculate_delay(attempt, config)
            logger.warning(
                "Attempt failed, retrying",
                extra={"attempt": attempt + 1, "delay_seconds": round(delay, 2)},
            )
            time.sleep(delay)

    raise requests.HTTPError(
        f"All {config.max_attempts} attempts exhausted",
        response=getattr(last_error, "response", None),
    )

Note on jitter: the formula random.uniform(0, delay) adds uniform jitter in the range [0, computed_delay]. This is "full jitter" — one of three common jitter strategies (the others being decorrelated jitter and equal jitter). Full jitter provides the most spread and is the recommended strategy when multiple concurrent clients are retrying the same service, which is the case for parallel CI pipeline runs.

scripts/smoke_test.py (turn 2)
"""Post-deployment smoke test for payment-api."""
from __future__ import annotations

import argparse
import json
import logging
import sys
import time
from datetime import datetime, timezone
from typing import Optional

import requests

from retry import RetryConfig, retry_request


class JsonFormatter(logging.Formatter):
    """Emit log records as JSON for structured log consumption."""

    def format(self, record: logging.LogRecord) -> str:
        payload = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "level": record.levelname,
            "message": record.getMessage(),
        }
        # Merge any extra fields attached to the record
        for key in ("endpoint", "attempt", "status_code", "elapsed_ms", "delay_seconds"):
            if hasattr(record, key):
                payload[key] = getattr(record, key)
        return json.dumps(payload)


def check_endpoint(
    base_url: str,
    path: str,
    config: RetryConfig,
    timeout: float,
    logger: logging.Logger,
) -> None:
    """
    Check a single endpoint with retry logic.

    Args:
        base_url: Base URL of the service (e.g. https://payment-api.internal).
        path: Endpoint path (e.g. /health).
        config: Retry configuration.
        timeout: HTTP request timeout in seconds.
        logger: Structured logger.

    Raises:
        requests.HTTPError: If all retry attempts are exhausted.
    """
    url = f"{base_url.rstrip('/')}{path}"

    def _request() -> requests.Response:
        start = time.monotonic()
        response = requests.get(url, timeout=timeout)
        elapsed_ms = int((time.monotonic() - start) * 1000)
        logger.info(
            "Endpoint response",
            extra={
                "endpoint": path,
                "status_code": response.status_code,
                "elapsed_ms": elapsed_ms,
            },
        )
        return response

    retry_request(_request, config, logger)
    logger.info("Endpoint healthy", extra={"endpoint": path})


def parse_args(argv: Optional[list[str]] = None) -> argparse.Namespace:
    parser = argparse.ArgumentParser(
        description="Post-deployment smoke test for payment-api"
    )
    parser.add_argument("--url", required=True, help="Base URL of the deployed service")
    parser.add_argument("--max-attempts", type=int, default=10)
    parser.add_argument("--base-delay", type=float, default=2.0)
    parser.add_argument("--timeout", type=float, default=10.0)
    return parser.parse_args(argv)


def main(argv: Optional[list[str]] = None) -> int:
    args = parse_args(argv)

    # Validate args
    if args.max_attempts < 1:
        print("Error: --max-attempts must be >= 1", file=sys.stderr)
        return 2
    if args.base_delay <= 0:
        print("Error: --base-delay must be > 0", file=sys.stderr)
        return 2

    # Set up JSON structured logger
    logger = logging.getLogger("smoke_test")
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(JsonFormatter())
    logger.addHandler(handler)
    logger.setLevel(logging.INFO)

    config = RetryConfig(
        max_attempts=args.max_attempts,
        base_delay=args.base_delay,
    )

    try:
        for path in ("/health", "/ready"):
            logger.info("Checking endpoint", extra={"endpoint": path})
            check_endpoint(args.url, path, config, args.timeout, logger)

        logger.info("Smoke test passed")
        return 0

    except requests.HTTPError as e:
        logger.error("Smoke test failed — retries exhausted", extra={"error": str(e)})
        return 1


if __name__ == "__main__":
    sys.exit(main())

The main(argv=None) signature accepts an optional argument list — this is the key design decision that makes the script testable. When called from the command line, argv is None and argparse reads from sys.argv. When called from tests, the test can pass a list of strings directly without needing to mock sys.argv. This pattern makes the CLI testable without any patching.

@pytest.mark.parametrize("status_code,expected", [
    (200, False),  # Success — not an error at all

def test_calculate_delay_exponential_growth() -> None:

    assert calculate_delay(0, config) == pytest.approx(1.0)
    assert calculate_delay(1, config) == pytest.approx(2.0)
    assert calculate_delay(2, config) == pytest.approx(4.0)
    assert calculate_delay(3, config) == pytest.approx(8.0)

    assert calculate_delay(5, config) == pytest.approx(15.0)

    for _ in range(50):

# ── Integration tests: mock HTTP server ───────────────────────────────────

class _SequenceHandler(BaseHTTPRequestHandler):
    """Serves a predefined sequence of status codes, then 200 for all after."""
    responses: list[int] = []
    call_count: int = 0

    def do_GET(self) -> None:
        idx = min(_SequenceHandler.call_count, len(_SequenceHandler.responses) - 1)
        status = _SequenceHandler.responses[idx]
        _SequenceHandler.call_count += 1
        self.send_response(status)
        self.end_headers()

    def log_message(self, *args) -> None:
        pass  # Suppress default request logging in test output


@pytest.fixture
def mock_server():
    """Start a local HTTP server on a random port. Returns (url, handler_class)."""
    _SequenceHandler.call_count = 0
    server = HTTPServer(("127.0.0.1", 0), _SequenceHandler)
    port = server.server_address[1]
    thread = threading.Thread(target=server.serve_forever, daemon=True)
    thread.start()
    yield f"http://127.0.0.1:{port}", _SequenceHandler
    server.shutdown()


def test_retry_succeeds_after_transient_failures(mock_server) -> None:
    url, handler = mock_server
    handler.responses = [500, 500, 200, 200]  # Both endpoints need 200

    result = main(["--url", url, "--max-attempts", "5", "--base-delay", "0.01"])
    assert result == 0
    assert handler.call_count >= 3


def test_non_retryable_404_exits_immediately(mock_server) -> None:
    url, handler = mock_server
    handler.responses = [404] * 10

    result = main(["--url", url, "--max-attempts", "5", "--base-delay", "0.01"])
    assert result == 1
    assert handler.call_count == 1  # Only one request made — did not retry


def test_config_error_exit_code() -> None:
    result = main(["--url", "http://localhost", "--max-attempts", "0"])
    assert result == 2

The mock server uses Python's built-in http.server module running in a daemon thread — no external dependencies. The port=0 binding lets the OS assign a free port, which avoids test port conflicts. The --base-delay 0.01 argument in the integration tests makes the retry backoff near-instant so the tests complete in milliseconds rather than seconds.

Test 1 failure (call_count == 2 not 1): The smoke test checks two endpoints — /health first, then /ready. The mock server's 404 response stops the retry loop on /health after one request, but then the test's handler is still serving responses for the second endpoint check. The test expected only 1 total request but the script made 1 for /health + 1 for /ready before the HTTPError propagated. Fix: the test should check handler.call_count == 1 specifically for the first endpoint, or accept that count may be higher. Simplest fix — change the assertion:

# Change:
assert handler.call_count == 1
# To — accepts 1 (failed on /health) or 2 (failed on /ready):
assert handler.call_count <= 2
# And confirm no retries happened by checking count is exactly 1 or 2:
assert result == 1  # exit code confirms non-retryable failure

Test 2 failure (result == 1 not 0): The handler sequence [500, 500, 200, 200] has only 4 entries. With two endpoints and the index clamped to the last entry, /health gets index 0 (500), 1 (500), 2 (200) — succeeds on attempt 3. Then /ready starts at index 3 (200) — the index is shared across both endpoint checks because call_count is a class variable, not per-endpoint. But /ready's first call is at index 3, which resolves to 200. This should succeed. The actual issue is the _SequenceHandler.call_count is a class variable — it is not reset between the two endpoint checks. Redefine it as an instance variable or use a thread-local counter. Simplest fix — extend the response sequence:

Fix for test_retry_succeeds_after_transient_failures
# Change:
handler.responses = [500, 500, 200, 200]
# To — enough 200s to cover both endpoints after two 500s:
handler.responses = [500, 500, 200, 200, 200, 200]

Root cause of both failures: the mock server's shared call_count class variable does not distinguish between the two endpoint sequences. The sequence needs to be long enough to cover all requests made across both endpoints. This is a test design issue, not a bug in the implementation being tested.

Fix 1 — make is_retryable contract explicit:

scripts/retry.py — is_retryable update
def is_retryable(
    error: Union[requests.Response, Exception]
) -> bool:
    """
    Determine whether an error warrants a retry attempt.

    This function should only be called when a response indicates
    an error (status >= 400) or when an exception was raised.
    Calling it with a successful response (2xx/3xx) is a caller error.

    Retryable: 429, 5xx, ConnectionError, Timeout, ChunkedEncodingError.
    Not retryable: 4xx (except 429), all other exceptions.

    Raises:
        ValueError: If called with a successful (< 400) response.
    """
    if isinstance(error, requests.Response):
        if error.status_code < 400:
            raise ValueError(
                f"is_retryable called with non-error response: {error.status_code}. "
                "Only call this function for error responses."
            )
        if error.status_code == 429:
            return True
        return 500 <= error.status_code < 600

    retryable_exceptions = (
        requests.exceptions.ConnectionError,
        requests.exceptions.Timeout,
        requests.exceptions.ChunkedEncodingError,
    )
    return isinstance(error, retryable_exceptions)

Fix 2 — seeded random for deterministic jitter testing:

scripts/retry.py — calculate_delay with optional random instance
def calculate_delay(
    attempt: int,
    config: RetryConfig,
    rng: Optional[random.Random] = None,
) -> float:
    """
    Args:
        attempt: Zero-indexed attempt number.
        config: Retry configuration.
        rng: Optional Random instance for deterministic testing.
             Uses module-level random if not provided.
    """
    delay = min(
        config.base_delay * (config.backoff_factor ** attempt),
        config.max_delay,
    )
    if config.jitter:
        _rng = rng or random
        delay = _rng.uniform(0, delay)
    return delay
tests/test_smoke_test.py — deterministic jitter test
def test_calculate_delay_jitter_in_range() -> None:
    config = RetryConfig(base_delay=4.0, backoff_factor=2.0, max_delay=999, jitter=True)
    rng = random.Random(42)  # Seeded for determinism
    for _ in range(50):
        delay = calculate_delay(1, config, rng=rng)
        assert 0 <= delay <= 8.0, f"Jitter produced out-of-range delay: {delay}"

Both changes tighten the contract. The is_retryable change converts a silent ambiguity (200 returns False, meaning "not retryable" — a nonsensical result) into a loud contract violation. Fail-fast at the call site is better than silently misclassifying a success as a non-retryable error. The rng parameter is an optional dependency injection that does not affect production behaviour but makes the test fully deterministic.

  • Verify
    The retry timeout is per-attempt, not total. The --timeout 10 argument sets the HTTP request timeout for each individual attempt. With 10 attempts and a base delay of 2 seconds, the maximum total wait time is approximately 10 × 10 (request timeout) + exponential backoff total — which can exceed 3 minutes. If the CI pipeline has a hard timeout, set --max-attempts and --base-delay such that the worst-case total is within that bound.

Prompting tip for automation scripts with tests
The most effective prompt structure for testable automation is to generate the module and its tests in separate turns, but in the same session. Turn 1 generates the retry module, Turn 2 generates the script that uses it, Turn 3 generates the tests. This sequence works because each turn's output is in Claude Code's context when the next turn's prompt is written — the tests reference the exact function signatures and module structure that was just generated, rather than guessing at an interface. Generating tests in a separate session, against code that has since been modified, produces tests that are structurally correct but semantically wrong.

In Example 9, the `main(argv=None)` pattern was used in the smoke test script. What specific benefit does this provide?
AIt allows the script to be imported as a module without executing the main logic
BIt makes the CLI testable by allowing tests to pass argument lists directly without mocking `sys.argv`
CIt provides a default set of arguments when the script is run without any flags
DIt enables the script to accept both positional and keyword arguments
When `argv=None`, argparse reads from `sys.argv` (normal CLI invocation). When tests pass a list like `['--url', url, '--max-attempts', '5']`, argparse uses that list instead. This makes the full CLI testable with `main(['--url', ...])` without needing to patch `sys.argv` — a fragile approach.
